# Умный подбор подрядчиков

Прототип рекомендательного сервиса для кейса HackAlem AI «Умный подбор подрядчиков». Проект помогает заказчику мероприятия выбрать до трёх подходящих исполнителей из уже сформированного каталога с учётом города, даты, формата мероприятия, категории, бюджета, языка и длительности.

Сервис предназначен для клиентов event-площадки, которым нужен короткий и объяснимый список доступных подрядчиков вместо ручного просмотра всего каталога.

## Что реализовано

- веб-форма для ввода параметров мероприятия;
- загрузка и нормализация каталога подрядчиков из CSV;
- проверка города и категории;
- исключение подрядчиков, занятых в выбранную дату;
- фильтрация по бюджету, формату мероприятия, языку и длительности;
- прозрачная оценка соответствия оставшихся кандидатов;
- NLP-сопоставление свободных пожеланий с описаниями подрядчиков через TF-IDF и косинусную близость;
- детерминированное ранжирование: одинаковый запрос возвращает одинаковый порядок;
- вывод не более трёх карточек с ценой, категорией, городом и объяснением выбора;
- отметка синтетических профилей;
- объяснение причин, по которым другие кандидаты не прошли фильтры;
- отдельные сообщения для трёх исходов: результат найден, категории нет в городе, кандидаты есть, но не проходят условия;
- автоматические тесты основных сценариев.

## Как работает решение

1. Пользователь выбирает город, дату, категорию подрядчика, формат мероприятия и бюджет. При необходимости указывает язык и длительность.
2. Приложение формирует структурированный запрос.
3. Модуль рекомендаций выбирает профили нужного города и категории.
4. Из выборки исключаются занятые, слишком дорогие и не соответствующие формату, языку или длительности кандидаты.
5. Каждый оставшийся профиль получает оценку соответствия. Она учитывает запас бюджета, NLP-релевантность описания запросу и запас по длительности.
6. Кандидаты сортируются по оценке, затем по цене и идентификатору. Дополнительные поля обеспечивают стабильный порядок при равных оценках.
7. Пользователь получает до трёх карточек с проверяемым объяснением либо понятную причину отсутствия результата.

## Технологии

- **Python 3.10+** — язык приложения;
- **Streamlit** — веб-интерфейс;
- **TF-IDF и косинусная близость** — собственная детерминированная реализация NLP-ранжирования на стандартной библиотеке;
- **csv, dataclasses, datetime, pathlib, re, math** — стандартная библиотека Python для чтения данных, моделей предметной области и обработки запросов;
- **unittest** — автоматические тесты.

В текущей версии внешние API, LLM и облачные сервисы не используются. Текстовая релевантность рассчитывается локально, а каждый фактор итоговой оценки отображается пользователю.

## Архитектура

```text
Пользователь
    │
    ▼
Streamlit-интерфейс (app.py)
    │  формирует SearchRequest
    ▼
Модуль рекомендаций (recommender.py)
    ├── загрузка и нормализация CSV
    ├── проверка обязательных условий
    ├── локальное TF-IDF/NLP-сопоставление
    ├── расчёт оценки соответствия
    └── формирование объяснений
    │
    ▼
Карточки рекомендаций или объяснение отсутствия результата

Источник данных: data/contractors.csv
Автотесты: tests/test_recommender.py
```

Основные компоненты:

- `app.py` — элементы формы и отображение результатов;
- `recommender.py` — модели данных, фильтрация, скоринг, сортировка и объяснения;
- `data/contractors.csv` — каталог подрядчиков;
- `tests/test_recommender.py` — проверки датасета, детерминизма и пограничных сценариев;
- `requirements.txt` — зависимость Streamlit.

## Установка и запуск

### 1. Клонировать репозиторий

```bash
git clone https://github.com/BAITC-Hacks/hack-57ec179f-nurseitai.git
cd hack-57ec179f-nurseitai
```

### 2. Создать виртуальное окружение

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

macOS или Linux:

```bash
source .venv/bin/activate
```

### 3. Установить зависимости

```bash
python -m pip install -r requirements.txt
```

### 4. Запустить приложение

```bash
python -m streamlit run app.py
```

После запуска Streamlit покажет локальный адрес приложения, обычно `http://localhost:8501`.

## Как проверить решение

### Сценарий с несколькими подходящими кандидатами

Введите следующие параметры:

| Параметр | Значение |
| --- | --- |
| Город | Алматы |
| Дата | 14.10.2026 |
| Категория | Ведущий |
| Формат | свадьба |
| Бюджет | 1 500 000 ₸ |
| Язык | русский |
| Длительность | 6 часов |

В поле дополнительных пожеланий можно указать: `интеллигентный ведущий для деловой аудитории`.

Ожидаемое поведение:

- система возвращает не более трёх подрядчиков;
- каждый подрядчик свободен в выбранную дату и проходит обязательные условия;
- карточка содержит индивидуальное объяснение;
- повторный запуск с теми же параметрами сохраняет порядок карточек.

Чтобы проверить влияние календаря, повторите запрос с датой **03.10.2026**. Для указанного набора условий система должна сообщить, что кандидаты есть, но никто не прошёл фильтры.

### Автоматические тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют:

- наличие 66 профилей с уникальными идентификаторами;
- ограничение выдачи тремя результатами;
- детерминированность порядка;
- изменение результата при смене даты;
- понятное состояние, когда в городе нет выбранной категории.

## Данные и интеграции

Проект использует локальный файл `data/contractors.csv`, предоставленный для хакатона. В нём содержатся 66 анонимизированных профилей со следующими данными:

- идентификатор и анонимное имя;
- категории услуг и город;
- минимальная цена;
- поддерживаемые форматы мероприятий и языки;
- максимальная длительность работы;
- занятые даты;
- текстовое описание;
- признаки синтетических и восстановленных значений.

Приложение не отправляет данные во внешние сервисы и не требует ключей API.

## Ограничения текущей версии

- используется только локальный каталог из 66 профилей;
- поддерживаются даты из диапазона, заданного интерфейсом: с 23.09.2026 по 31.12.2026;
- нет регистрации пользователей, бронирования, заявок, оплаты и уведомлений подрядчиков;
- нет административного интерфейса для изменения каталога;
- нет сохранения истории запросов;
- NLP-ранжирование использует TF-IDF, но не учитывает глубокую семантику так же, как embedding- или LLM-модель;
- цена трактуется как минимальная цена из каталога, итоговая стоимость не рассчитывается;
- доступность определяется только списком занятых дат из CSV;
- приложение не развёрнуто в отказоустойчивой производственной инфраструктуре.

## Развёрнутая версия

Публичная deployed-версия на текущий момент отсутствует. Проект запускается локально по инструкции выше.
